What we learned

Written specs, one pull request each.

Each piece of work started as a GitHub issue stating the problem and its acceptance criteria. Devin opened a pull request; CI, Devin Review and, for fixes, Bug Smasher's own verifier checked it before a person merged it.

From 02:06 on 30 Sep, Bug Smasher built itself.

A label on an issue in its own repository started Devin, and the service tracked the work through review and verification to the merge.

Only critical findings were fixed before merging.

Review findings that could break a run were fixed in the same pull request. Everything else became a deferred issue, listed as a known limitation.
