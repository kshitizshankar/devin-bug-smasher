The solution

Bug Smasher turns that queue into a pipeline: Devin investigates and fixes, Bug Smasher tests, a human decides

1

Investigation in minutes

Every labelled bug gets its own Devin session, which reproduces it, finds the cause and writes a test that fails today

2

Proof, not a claim

Bug Smasher reruns Devin’s test in the project’s own test image. No pass, no merge

3

Runs in the team’s GitHub

A label starts it. A human decides and merges. Nothing new to learn

Devin features used

Sessions API · one per bugStructured outputA machine per sessionGitHub integrationDevin ReviewACU cap per session

Playbooks we wrote

  • Triage: reproduce, find the cause, propose a test that fails today
  • Repair: failing test first, then the fix; keep every test
  • Feature: one test per acceptance criterion

Bug Smasher’s verifier

  • Runs Devin’s test in the project’s image, network off
  • Must fail on the old code and pass on the fix
  • Refuses weakened tests; flags silenced checks
  • Tests again after the merge
Order as implemented: the test runs first; Devin Review is requested once it passes. Every step leaves a trace on GitHub. Source: Bug Smasher code (src/orchestrator), README and docs/ARCHITECTURE.md.3

Why Devin

Devin makes this practical: it supplies the agent’s machine, tools and memory, so a team builds only the workflow

What fixing bug #1 took

  1. Work in a full Superset checkout
  2. Run its test suite
  3. Reproduce the failure
  4. Trace the cause in the code
  5. Write a test that fails today
  6. Fix it and open a pull request
  7. Summarise it for the reviewer

A real machine, many steps, and memory across hours
